# WebSocket＋JSON 送受信サンプル

ブラウザーとPythonの両方で「送信」「受信」を学ぶ、同じPC内で動くサンプルです。音声認識、BGM、ROS、ロボットは不要です。既存アプリと `reference/` は変更しません。

## 1. 通信の流れ

```text
ブラウザー（client.html）              Python（server.py）
          ─────── 接続要求 ────────────→ 待ち受け
          ←───── 接続通知のJSON ──────── 接続直後に送信
文字入力  ─────── 文字のJSON ──────────→ 受信・解析
画面表示  ←───── 返信のJSON ──────────── 返信を送信
```

| 学ぶ処理 | コードの目印 | 内容 |
| --- | --- | --- |
| ブラウザーの送信 | client.html の B6 | オブジェクトをJSON文字列にして送る |
| Pythonの受信 | server.py の P4・P3 | 文字列を受け取り、JSONを解析する |
| Pythonの送信 | server.py の P2 | 辞書をJSON文字列にして送る |
| ブラウザーの受信 | client.html の B4 | JSON文字列を解析し、内容を表示する |

接続通知は、ブラウザーが文字を送る前にPythonから送られます。返信は、ブラウザーが文字を送った後にPythonから送られます。WebSocketでは、サーバーも自分からメッセージを送れます。このサンプルでPythonの送信を始めるきっかけは「接続」と「受信」です。

## 3. 準備（初回のみ）

Python 3.11または3.12と、ChromeまたはEdgeなどのブラウザーを用意してください。以下はWindowsの **Git Bash** 用です。PowerShellへそのまま貼り付けるコマンドではありません。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
py -3.11 -m venv .venv
source .venv/Scripts/activate
python -m pip install -r requirements.txt
```

`py -3.11` がPythonを検出できない場合は、`python --version` で3.11または3.12であることを確認し、仮想環境作成の行だけ `python -m venv .venv` に置き換えてください。3.12をランチャーから起動する場合は `py -3.12 -m venv .venv` も使えます。

このフォルダ専用の `.venv` を使います。プロジェクト直下の既存アプリ用 `.venv` とは別の場所です。仮想環境はライブラリをアプリごとに分ける仕組みで、`activate` は今回使うPythonを切り替えます。`websockets` は接続・送受信・終了を担当するライブラリです。

## 4. 起動と操作

### ターミナルA：WebSocketサーバー

Git Bashで次を実行します。初回準備から続ける場合、移動と有効化は済んでいます。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
source .venv/Scripts/activate
python server.py
```

`待ち受け ws://127.0.0.1:8765` と表示されたら、このターミナルを開いたままにします。

### ターミナルB：画面の配信

別のGit Bashで次を実行します。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
source .venv/Scripts/activate
python -m http.server 8000 --bind 127.0.0.1 --directory .
```

ブラウザーで [サンプル画面](http://127.0.0.1:8000/client.html) を開きます。HTMLをダブルクリックするのではなく、このURLを使ってください。

### 操作

1. 「接続」を押します。「接続済み」になり、Pythonからの接続通知が履歴に出ます。
2. 入力欄の「こんにちは」を「送信」します。Enterでも送れます。
3. ブラウザーの履歴で「送信 → Python」「受信 ← Python」を確認します。
4. ターミナルAで「受信 ← ブラウザー」「送信 → ブラウザー」を確認します。
5. 文字を変え、接続したまま何度か送信します。
6. 「切断」を押します。送信ボタンが無効になります。
7. 「接続」で新しい接続を開始できます。過去の文字は再送しません。

通信履歴は画面内だけに保持し、直近200行を表示します。再読み込みで消えます。

### 終了

ブラウザーで「切断」を押し、ターミナルAとBのそれぞれで **Ctrl+C** を押します。仮想環境を終了する場合は、それぞれで `deactivate` を実行します。次回起動時に仮想環境の作成やインストールを繰り返す必要はありません。

## 5. ログの読み方

ブラウザーでは以下のように表示されます（時刻は例）。

```text
[14:00:00] 受信 ← Python {"type": "connected", "text": "接続しました"}
[14:00:00] 内容 接続しました
[14:00:05] 送信 → Python {"type":"message","text":"こんにちは"}
[14:00:05] 受信 ← Python {"type": "reply", "text": "受信しました：こんにちは"}
[14:00:05] 内容 受信しました：こんにちは
```

ターミナルAでは同じ通信を反対側から確認できます。

```text
[14:00:00] 送信 → ブラウザー {"type": "connected", "text": "接続しました"}
[14:00:05] 受信 ← ブラウザー {"type":"message","text":"こんにちは"}
[14:00:05] 送信 → ブラウザー {"type": "reply", "text": "受信しました：こんにちは"}
```

JSONの空白の有無は意味を変えません。「送信」表示は送信を予約したことを表し、Pythonの受信・解析を確認できるのは返信が届いたときです。

## 6. HTTP・WebSocket・JSONの違い

| 用語 | 今回の役割 |
| --- | --- |
| HTTP | ポート8000でHTMLをブラウザーに届ける。画面読み込み用 |
| WebSocket | ポート8765で接続を維持し、双方からメッセージを送る |
| JSON | データを文字列で表現する形式。通信方式そのものではない |
| 127.0.0.1 | 自分のPCを指すアドレス。今回、別PCからは接続できない |
| ポート | PC内のどの待ち受け先へ接続するかを示す番号 |

HTTPサーバーだけではWebSocket通信はできません。WebSocketサーバーだけでは画面を配信しません。そのため2つのターミナルを使います。

今回のJSONは `type`（種類）と `text`（内容）を持ちます。

```json
{"type":"message","text":"こんにちは"}
```

JavaScriptでは `JSON.stringify()`、Pythonでは `json.dumps()` でJSON文字列を作ります。JavaScriptの `JSON.parse()`、Pythonの `json.loads()` で、文字列をプログラムで扱えるデータへ戻します。`message` はブラウザーからの入力、`connected`・`reply`・`error` はPythonからの接続通知・返信・形式エラーです。

## 7. コードを読む順番

1. **P1・B1：準備**。ライブラリと画面部品を確認します。
2. **P5：待ち受け**。`serve()` が接続を受け付け、`handle_connection()` を呼びます。
3. **B3：接続**。`new WebSocket()` の直後は接続途中で、`open` イベントが完了を知らせます。
4. **P4 → P2 → B4：接続通知**。Pythonが送信し、ブラウザーが受信します。
5. **B6 → P4 → P3 → P2 → B4：文字の往復**。ブラウザーの送信、Pythonの受信・返信、ブラウザーの受信を追います。
6. **B2・B5・B7：状態と終了**。未接続時の送信抑止と切断を確認します。

### async と await

Pythonの `async def` は、通信などを待ちながら進める関数を定義します。`await` は完了を待ち、その待ち時間をほかの通信処理に譲ります。`async for` は届いたメッセージを順に処理するループです。`asyncio.run()` がこれらを動かす仕組みを開始し、`async with` は終了時に接続やサーバーを片付けます。

### ブラウザーのイベント

`addEventListener()` は「出来事が起きたら実行する処理」を登録します。`click` はボタン操作、`submit` はフォーム送信、WebSocketの `open` は接続完了、`message` は受信、`error` は通信エラー、`close` は切断です。通信結果を待つループで画面を止める必要はありません。

### エラーと切断

PythonはJSONの型を確認してから返信します。不正なJSON・配列・違う `type` などには説明を返し、同じ接続で次のメッセージを待ちます。切断された接続の処理は終了し、サーバー自体は次の接続を受け付けます。ブラウザーは自動再接続せず、未送信データをためません。受信した文字は `textContent` で表示するため、HTMLとして解釈しません。

## 8. 練習

- 入力する文字を変えて送信し、双方のログを比べます。
- P3の「受信しました：」を変更し、PythonをCtrl+Cで停止して再起動します。再接続して返信を確認します。
- P4の「接続しました」を変更し、再起動・再接続します。入力前に新しい通知が届くことを確認します。
- `<b>こんにちは</b>` を送信します。太字として解釈されず、文字のまま表示されることを確認します。

HTMLの変更後は画面を再読み込みして接続し直してください。

## 9. トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| `No module named 'websockets'` | 専用仮想環境を有効にし、`python -m pip install -r requirements.txt` を実行する |
| ポート使用中 | すでに動いているサンプルがあればCtrl+Cで停止する。別アプリのポート使用状況も確認する |
| 画面が開けない | ターミナルBの起動と、URLが `http://127.0.0.1:8000/client.html` か確認する |
| 404が出る | ターミナルBが `communication_test/` 内で起動しているか確認する |
| 画面は開くが接続できない | ターミナルAの待ち受け表示を確認する。HTTPとWebSocketは別のサーバー |
| 切断コード1006 | 通常の終了手順を完了できなかった可能性がある。サーバー停止や接続失敗をログで確認する |
| `py -3.11` が使えない | 「準備」の `python -m venv .venv` による代替手順を参照する |
| 変更が反映されない | Pythonは再起動、HTMLは再読み込みして再接続する |

## 10. 自動テスト

`communication_test/` に移動し、専用の仮想環境を有効にして実行します。

```bash
python -m unittest discover -s tests -v
```

空きポートでサーバーを一時起動し、実際のローカルWebSocket接続を使います。接続通知、日本語の往復、不正形式への応答と処理継続、切断後の新しい接続を確認します。通常のサーバーを起動しておく必要はありません。ブラウザーの表示とボタン操作は自動テストに含まれず、「起動と操作」の手順で確認します。
