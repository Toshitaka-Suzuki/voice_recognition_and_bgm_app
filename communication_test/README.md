# WebSocket＋JSON 送受信サンプル

ブラウザーとPythonの両方で「送信」「受信」を学ぶサンプルです。同じPC内でも、有線LANで接続した別PCでも使用できます。音声認識、BGM、ROS、ロボットは不要です。既存アプリと `reference/` は変更しません。

文字の往復に加えて、各信号を独立して試せます。信号ボタンとPythonの数字キーの使い方、JSON一覧は [信号の模擬送受信ガイド](signals-guide.md) を参照してください。Python側のキー操作はWindows TerminalのPowerShellで起動します。

## 1. 通信の流れ

```text
ブラウザー（client.html）              Python（server.py）
          ─────── 接続要求 ────────────→ 待ち受け
          ←───── 接続通知のJSON ──────── 接続直後に送信
文字入力  ─────── 文字のJSON ──────────→ 受信・解析
画面表示  ←───── 返信のJSON ──────────── 返信を送信
```

| 学ぶ処理 | コードの目印 | 内容 |
| --- | --- | --- |
| ブラウザーの送信 | client.html の B6 | オブジェクトをJSON文字列にして送る |
| Pythonの受信 | server.py の P4・P3 | 文字列を受け取り、JSONを解析する |
| Pythonの送信 | server.py の P2 | 辞書をJSON文字列にして送る |
| ブラウザーの受信 | client.html の B4 | JSON文字列を解析し、内容を表示する |

接続通知は、ブラウザーが文字を送る前にPythonから送られます。返信は、ブラウザーが文字を送った後にPythonから送られます。WebSocketでは、サーバーも自分からメッセージを送れます。このサンプルでPythonの送信を始めるきっかけは「接続」と「受信」です。

## 3. 準備（初回のみ）

Python 3.11または3.12と、ChromeまたはEdgeなどのブラウザーを用意してください。以下はWindowsの **Git Bash** 用です。PowerShellへそのまま貼り付けるコマンドではありません。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
py -3.11 -m venv .venv
source .venv/Scripts/activate
python -m pip install -r requirements.txt
```

`py -3.11` がPythonを検出できない場合は、`python --version` で3.11または3.12であることを確認し、仮想環境作成の行だけ `python -m venv .venv` に置き換えてください。3.12をランチャーから起動する場合は `py -3.12 -m venv .venv` も使えます。

このフォルダ専用の `.venv` を使います。プロジェクト直下の既存アプリ用 `.venv` とは別の場所です。仮想環境はライブラリをアプリごとに分ける仕組みで、`activate` は今回使うPythonを切り替えます。`websockets` は接続・送受信・終了を担当するライブラリです。

## 4. 同じPCでの起動と操作

### ターミナルA：WebSocketサーバー

以下のGit Bash手順は文字の送受信用です。数字キーで信号を送る場合は、[PowerShellでの起動手順](signals-guide.md#2-起動する) を使ってください。

Git Bashで次を実行します。初回準備から続ける場合、移動と有効化は済んでいます。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
source .venv/Scripts/activate
python server.py
```

`待ち受け ws://127.0.0.1:8765` と表示されたら、このターミナルを開いたままにします。

### ターミナルB：画面の配信

別のGit Bashで次を実行します。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
source .venv/Scripts/activate
python -m http.server 8000 --bind 127.0.0.1 --directory .
```

ブラウザーで [サンプル画面](http://127.0.0.1:8000/client.html) を開きます。HTMLをダブルクリックするのではなく、このURLを使ってください。

### 操作

1. 「接続」を押します。「接続済み」になり、Pythonからの接続通知が履歴に出ます。
2. 入力欄の「こんにちは」を「送信」します。Enterでも送れます。
3. ブラウザーの履歴で「送信 → Python」「受信 ← Python」を確認します。
4. ターミナルAで「受信 ← ブラウザー」「送信 → ブラウザー」を確認します。
5. 文字を変え、接続したまま何度か送信します。
6. 「切断」を押します。送信ボタンが無効になります。
7. 「接続」で新しい接続を開始できます。過去の文字は再送しません。

通信履歴は画面内だけに保持し、直近200行を表示します。再読み込みで消えます。

### 終了

ブラウザーで「切断」を押し、ターミナルAとBのそれぞれで **Ctrl+C** を押します。仮想環境を終了する場合は、それぞれで `deactivate` を実行します。次回起動時に仮想環境の作成やインストールを繰り返す必要はありません。

## 4.1 別PC・有線LANでの起動と操作

```text
PC A（Python） ←── WebSocket＋JSON／有線LAN ──→ PC B（ブラウザー）
                                                ↑ HTTP
                                         PC B内の画面配信
```

PC Aは `server.py`、PC Bは `client.html` を使います。PC AのHTTPサーバーは不要です。PC BはPython標準機能だけで画面を配信するので、仮想環境や `websockets` の導入は不要です。

### 手順1：LANとIPアドレスを確認する

両PCを同じルーター／スイッチの有線LANへ接続します。ケーブルで直接接続する場合も、両PCのIP設定が必要です。ケーブルをつなぐだけで必ず通信できるとは限りません。このサンプルはIP設定を自動変更しません。

両PCでターミナルを開き、次を実行します（Git Bashでも実行できます）。

```bash
ipconfig
```

使用中の **イーサネットアダプター** のIPv4アドレスとサブネットマスクを確認してください。Wi-Fiや仮想アダプターのアドレスと混同しないようにします。以下の例は、両PCが同じサブネットで、互いに通信できる設定になっている前提です。

| 項目 | 説明用の例 |
| --- | --- |
| PC AのIPv4 | 192.168.10.10 |
| PC BのIPv4 | 192.168.10.20 |
| 両PCのサブネットマスク | 255.255.255.0 |

**これらは例です。実際の値へ置き換えてください。** IPアドレスをこの例へ無理に変更する必要はありません。異なるサブネットでは適切なルーティングが必要です。IP設定が不明な場合はネットワーク管理者に確認してください。

### 手順2：PC Aでサーバーを起動する

PC Aで「準備」の専用仮想環境と依存を用意し、Git Bashで次を実行します。`--host` には **PC A自身の有線LANのIPv4** を指定します。PC BのIPではありません。

```bash
cd /d/Program_Folder/Codex_ws/voice_recognition_app/communication_test
source .venv/Scripts/activate
python server.py --host 192.168.10.10 --port 8765
```

フォルダの場所もPC Aの実際の配置先へ置き換えてください。`待ち受け ws://192.168.10.10:8765` の表示を確認します。アドレスが変わった場合は、新しい値でサーバーを再起動してください。

### 手順3：PC BにHTMLを配置し、画面を配信する

PC Bの任意の作業フォルダ（例：`D:\websocket_client`）を用意し、このサンプルの `client.html` だけをコピーします。Python 3.11または3.12が使える状態で、Git Bashからそのフォルダへ移動します。

```bash
cd /d/websocket_client
python -m http.server 8000 --bind 127.0.0.1 --directory .
```

PC Bのブラウザーで [http://127.0.0.1:8000/client.html](http://127.0.0.1:8000/client.html) を開きます。ここでの `127.0.0.1` は **PC B** です。画面配信はPC B内だけなので、PC BのTCP 8000をLANへ開放する必要はありません。

### 手順4：PC BからPC Aへ接続する

画面の「WebSocket接続先」を次の例のように変更して「接続」を押します。

```text
ws://192.168.10.10:8765
```

この値には **PC Aの実際のIPとサーバー起動時のポート** を使います。PC Bで `ws://127.0.0.1:8765` を指定すると、PC AではなくPC B自身へ接続しようとします。

「こんにちは」を送信し、PC Bの画面で送受信履歴、PC Aのターミナルで受信・返信ログを確認します。接続先欄は接続途中・接続中・切断途中は編集できません。「切断」の完了後に変更できます。空欄・不正URL・HTTPのURLは、説明を表示して接続しません。再読み込みでは接続先が既定値へ戻るため、LAN用の値を再入力してください。

### 起動引数と待ち受けの意味

| 指定 | 意味 |
| --- | --- |
| 引数なし | `127.0.0.1:8765`。同じPCの通信を維持 |
| `--host PC AのIPv4` | PC Aの指定したネットワークアドレスで待ち受ける |
| `--port 9001` | ポートを9001へ変更する。ブラウザー側も9001へ変更する |
| `--help` | 起動引数の説明を表示する |

`--host` はサーバーが受け付ける自分のアドレス、画面の接続先はブラウザーが接続する相手のアドレスです。LAN手順ではどちらにもPC Aの同じIPを使います。ポートは1〜65535の整数だけを受け付けます。

### 接続できない場合の確認順

1. **待ち受け**：PC Aのログと `--host` が有線LANのIPv4と一致するか確認します。`127.0.0.1` では別PCから受け付けません。
2. **接続先**：PC Bの画面が `ws://PC AのIP:ポート` か確認します。
3. **ポート**：双方が同じ番号で、他のアプリと競合していないか確認します。PC BのPowerShellで `Test-NetConnection 192.168.10.10 -Port 8765` を使うとTCP接続の可否を確認できます。IP・ポートは実際の値へ置き換えます。
4. **LAN**：ケーブル、リンク状態、IPとサブネット、経路を確認します。pingが失敗しても、ICMPが制限されている場合があるので、それだけでWebSocket通信不可とは判断しません。
5. **Windowsファイアウォール**：PC AへのTCP受信が許可されているか確認します。

### PC Aのファイアウォール設定が必要な場合

管理者権限が必要な場合があります。PC Aの「セキュリティが強化されたWindows Defenderファイアウォール」で手動設定します。

1. 「受信の規則」→「新しい規則」→「ポート」を選びます。
2. 「TCP」と「特定のローカルポート」を選び、`8765`（変更した場合はその番号）を入力します。
3. 「接続を許可する」を選び、使用するLANに対応するプロファイルだけを選びます。プロファイルは実際のネットワークと一致させます。
4. 名前を「WebSocket学習サンプル TCP 8765」などとします。
5. 作成した規則のプロパティの「スコープ」で、リモートIPアドレスを「これらのIPアドレス」にし、**PC Bの実際のIPv4だけ**を追加します。
6. 規則を確認してから接続を試します。PC BのIPが変わった場合はスコープも更新します。不要になったら、このサンプル用の規則を無効化または削除します。

規則の設定中はサーバーを停止しておき、PC Bへの制限まで設定してから起動してください。既存の管理ポリシーで設定できない場合は管理者へ相談してください。[Microsoftの設定資料](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure)

このサンプルはファイアウォールを自動変更しません。信頼できるLAN内の学習用です。サーバーには認証とTLSを実装しておらず、LAN手順は `ws://` を使います。入力欄は `wss://` も受け付けますが、このサーバーをそのまま暗号化通信に切り替えるものではありません。

## 5. ログの読み方

ブラウザーでは以下のように表示されます（時刻は例）。

```text
[14:00:00] 受信 ← Python {"type": "connected", "text": "接続しました"}
[14:00:00] 内容 接続しました
[14:00:05] 送信 → Python (ws://127.0.0.1:8765/) {"type":"message","text":"こんにちは"}
[14:00:05] 受信 ← Python {"type": "reply", "text": "受信しました：こんにちは"}
[14:00:05] 内容 受信しました：こんにちは
```

ターミナルAでは同じ通信を反対側から確認できます。

```text
[14:00:00] 送信 → ブラウザー {"type": "connected", "text": "接続しました"}
[14:00:05] 受信 ← ブラウザー {"type":"message","text":"こんにちは"}
[14:00:05] 送信 → ブラウザー {"type": "reply", "text": "受信しました：こんにちは"}
```

JSONの空白の有無は意味を変えません。「送信」表示は送信を予約したことを表し、Pythonの受信・解析を確認できるのは返信が届いたときです。

## 6. HTTP・WebSocket・JSONの違い

| 用語 | 今回の役割 |
| --- | --- |
| HTTP | ポート8000でHTMLをブラウザーに届ける。画面読み込み用 |
| WebSocket | ポート8765で接続を維持し、双方からメッセージを送る |
| JSON | データを文字列で表現する形式。通信方式そのものではない |
| 127.0.0.1 | 操作しているPC自身を指すアドレス。別PCへは、そのPCのLANアドレスを指定する |
| ポート | PC内のどの待ち受け先へ接続するかを示す番号 |

HTTPサーバーだけではWebSocket通信はできません。WebSocketサーバーだけでは画面を配信しません。そのため2つのターミナルを使います。

文字送受信のJSONは `type`（種類）と `text`（内容）を持ちます。信号では `name`・`value`・`count` も使います。詳細は [信号ガイド](signals-guide.md) を参照してください。

```json
{"type":"message","text":"こんにちは"}
```

JavaScriptでは `JSON.stringify()`、Pythonでは `json.dumps()` でJSON文字列を作ります。JavaScriptの `JSON.parse()`、Pythonの `json.loads()` で、文字列をプログラムで扱えるデータへ戻します。`message` はブラウザーからの入力、`connected`・`reply`・`error` はPythonからの接続通知・返信・形式エラーです。

## 7. コードを読む順番

1. **P1・B1：準備**。ライブラリと画面部品を確認します。
2. **P5：待ち受け**。`serve()` が接続を受け付け、`handle_connection()` を呼びます。
3. **B3：接続**。`new WebSocket()` の直後は接続途中で、`open` イベントが完了を知らせます。
4. **P4 → P2 → B4：接続通知**。Pythonが送信し、ブラウザーが受信します。
5. **B6 → P4 → P3 → P2 → B4：文字の往復**。ブラウザーの送信、Pythonの受信・返信、ブラウザーの受信を追います。
6. **B2・B5・B7：状態と終了**。未接続時の送信抑止と切断を確認します。
7. **P6・B8：別PCへの接続**。`argparse` で起動引数を読み取り、入力欄のURLを検証してから接続します。
8. **P7・P8・P9・B9・B10・B11：信号の送受信**。入力の検証、受付通知、キー操作による出力、画面表示を追います。

### async と await

Pythonの `async def` は、通信などを待ちながら進める関数を定義します。`await` は完了を待ち、その待ち時間をほかの通信処理に譲ります。`async for` は届いたメッセージを順に処理するループです。`asyncio.run()` がこれらを動かす仕組みを開始し、`async with` は終了時に接続やサーバーを片付けます。

### ブラウザーのイベント

`addEventListener()` は「出来事が起きたら実行する処理」を登録します。`click` はボタン操作、`submit` はフォーム送信、WebSocketの `open` は接続完了、`message` は受信、`error` は通信エラー、`close` は切断です。通信結果を待つループで画面を止める必要はありません。

### エラーと切断

PythonはJSONの型を確認してから返信します。不正なJSON・配列・違う `type` などには説明を返し、同じ接続で次のメッセージを待ちます。切断された接続の処理は終了し、サーバー自体は次の接続を受け付けます。ブラウザーは自動再接続せず、未送信データをためません。受信した文字は `textContent` で表示するため、HTMLとして解釈しません。

## 8. 練習

- 入力する文字を変えて送信し、双方のログを比べます。
- P3の「受信しました：」を変更し、PythonをCtrl+Cで停止して再起動します。再接続して返信を確認します。
- P4の「接続しました」を変更し、再起動・再接続します。入力前に新しい通知が届くことを確認します。
- `<b>こんにちは</b>` を送信します。太字として解釈されず、文字のまま表示されることを確認します。

HTMLの変更後は画面を再読み込みして接続し直してください。

## 9. トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| `No module named 'websockets'` | 専用仮想環境を有効にし、`python -m pip install -r requirements.txt` を実行する |
| ポート使用中 | すでに動いているサンプルがあればCtrl+Cで停止する。別アプリのポート使用状況も確認する |
| 画面が開けない | ターミナルBの起動と、URLが `http://127.0.0.1:8000/client.html` か確認する |
| 404が出る | ターミナルBが `communication_test/` 内で起動しているか確認する |
| 画面は開くが接続できない | ターミナルAの待ち受け表示を確認する。HTTPとWebSocketは別のサーバー |
| 切断コード1006 | 通常の終了手順を完了できなかった可能性がある。サーバー停止や接続失敗をログで確認する |
| `py -3.11` が使えない | 「準備」の `python -m venv .venv` による代替手順を参照する |
| 変更が反映されない | Pythonは再起動、HTMLは再読み込みして再接続する |

## 10. 自動テスト

`communication_test/` に移動し、専用の仮想環境を有効にして実行します。

```bash
python -m unittest discover -s tests -v
```

空きポートでサーバーを一時起動し、実際のローカルWebSocket接続を使います。接続通知、日本語の往復、不正形式への応答と処理継続、切断後の新しい接続に加え、起動引数の既定値・指定値・不正ポートと、指定アドレス・ポートでの待ち受けを確認します。通常のサーバーを起動しておく必要はありません。ブラウザーの表示とボタン操作は自動テストに含まれず、上記の操作手順で確認します。

信号のテストでは、全入力の受付、全状態・判定結果の出力、任意順序と繰り返し、不正な残り回数、複数接続への出力、切断後の継続、過去信号を再送しないことを確認します。

2台での受け入れ確認では、PC Bの接続先をPC AのIPへ変更し、接続通知、文字の往復、双方のログ、切断後の送信無効化、手動再接続を確認します。LANを抜いた場合は、ライブラリの切断検出に時間がかかる場合があります。TCPの接続可否と、WebSocketで返信が返ることは別々に確認してください。

## 11. 模擬送受信する信号

入力・出力はPython側を基準にしています。以下の信号は、順序を制限せず個別に送受信できます。操作一覧と全JSONは [信号ガイド](signals-guide.md) にあります。

| 方向 | 信号 |
| --- | --- |
| 出力 | 状態通知：スタンバイ、開始前インタビュー、開始前インタビュー終了、終了インタビュー、終了インタビュー終了 |
| 出力 | パリイ判定結果 |
| 入力 | ゲームスタート、戦闘開始、パリイ、弱点カウント数、戦闘終了 |

入力信号には受付通知を返します。弱点カウントは残り回数です。Pythonの1〜5キーで状態、6・7キーでパリイ結果を全接続へ送信します。ゲームの進行、自動判定、自動減算は行いません。接続直後は接続通知だけを送り、過去の出力信号は再送しません。本体・ROSとの連携、定期通知、自動再接続は含めません。
